# ベースアイデアノート

## 概要
リアルな会話体験を実現する、英会話トレーニングエージェント


## 解決する課題
既存のAI英会話アプリは、
- 一対一での会話
- 話題にリアル性がない
- 複数人で会話に入れない、というリアル感がない
といった現実との乖離という大きな課題がある。
これを解決する。

## 提供する機能
- 複数人での会話を提供（2 ~ 4人をユーザーが選択）エージェントがそれによって人数増えるイメージ。
- トピックはあらかじめ3つくらい用意
- ユーザーは任意のトピックを指定することもできる。
- x API を用いて、最新ニュース・トレンドを取得して話題を決めるモードも提供
    - そのモードが選ばれたら、自動でx apiを叩き、話題を決める
- エージェントはターン制で会話する。つまり、ユーザーが一度発話したら、少なくともAIエージェントはそれを絶対に遮らない。
- Gemini Live APIには「barge-in」、つまりユーザーがモデルを割り込める機能があるので、ユーザーはAI agentの話を遮ることができる。
- 一定時間（最小1s）ユーザーが発話しなければ、AIが喋り始める。
- その待ち時間は、ユーザーが
- AIエージェントは、会話するエージェントが会話を続ける間に、文法の間違いを記録していき（tool call）、適宜表示し、会話が終わった後に見返すことができる。（TTL 24h）
- AI エージェントは、会話を適宜圧縮する。（並列）
- ユーザーはUIのみからAIエージェントと会話できる。
- AIエージェントの応答は、チャットに文章が表示されながら、音声も表示される。
- （可能なら）ユーザーの発話を文字起こしする。
- 吹き出しのやり取りのようなUIになる

    - Elasticsearch（スポンサー）

## 審査基準

1. **AIエージェントが価値の中心になっているか**
単なる機能ではなくAIエージェントが作品の中核として機能しているか、自律的な振る舞い（判断・タスク実行）があるか、“AIエージェントである必然性”があるか等を評価します。
2. **設定した課題へのアプローチ力**
    
    設定した課題とその背景、対象となるユーザー、作品が提供する価値といったプロダクトとしてのストーリーに一貫性、妥当性、新規性があるか等を評価します。
    
3. **ユーザビリティ**
    
    ユーザーが直観的に使える機能やデザインを有しているかを評価します。
    
4. **実用性・体験価値の魅力**
    
    設定した課題の解決に対する実用性、また作品がどこまで効果的にアプローチできているかを評価します。また提供する体験価値が突き抜けているか等も加点評価します。
    
5. **実装力**
    
    選定した技術や構成の納得度、拡張性や実運用への配慮など、利用を必須としたツールを活用したうえで、これらがどれだけ実現できているかを総合的に評価します。

## その他メモ
特に重要な設計論点

1つ目は、複数人会話をどう自然に見せるかです。
AIがただ順番に話すだけだと不自然なので、Conversation Manager Agentが「次に誰が話すか」「誰がユーザーに質問を振るか」「誰が相槌だけにするか」を管理する必要があります。

2つ目は、ターン制とbarge-inの両立です。
ユーザー発話中はAIが割り込まない。一方で、AI発話中はユーザーが遮れる。この非対称性がリアルな体験にかなり効きます。Gemini Live APIにはbarge-inがありますが、「AIがユーザーを遮らない」はアプリ側のVAD、無音検知、turn managerで制御する部分です。

3つ目は、文法フィードバックを会話体験の邪魔にしないことです。
会話中に逐一訂正されるとリアルな会話から離れます。なので、会話中は小さく記録・軽く表示、会話後にまとめて復習、がよさそうです。
